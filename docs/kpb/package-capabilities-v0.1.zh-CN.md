# KPB 包能力增量提案：中文设计说明

本文件是[英文主提案](../../spec/framework/package-capabilities-v0.1-proposal.md)的辅助说明，发生差异时以英文为准。状态：本地可审阅草案，尚未合并或采纳。

## 建议落实的最小方案

三仓责任与包能力分开看：machine 维护规范、检查实现与验收；adva 保留问题、解释、方法、实验和证据；library 提供最小可扩展的材料承载核心。包至少声明计算、验证、图书馆中的一种，可以兼具，但声明不会自动赋予执行或验证权威。

library 的最小核心先取三组内容：身份与版本引用；材料、注释和类型明确的关系；来源与版本化扩展。学习进度、搜索索引、交互状态和媒介执行留在外部。扩展可以丰富呈现，但不能改变旧接收规则或替自己授予验证权威。

library 以内容为主，但至少还要有可运行的引用链接机制与工具。本次新增离线 Git 引用查找器：调用方独立指定仓库与消费 commit，工具按精确 repository/commit/path 读取原始 blob 并检查可选摘要，不联网、不跟随脏工作区、不自动升级版本。缺失、unsupported、incompatible 与预算耗尽分别可见；定位字节仍不等于语义接纳。工具本次只在 machine 试点，并未部署或修改 library 仓库。

本次把其中最小的一块做成可运行原型：一个严格 JSON schema、一份四个原创材料/两条路径的 library-only 示例和有限检查器。同一材料可以被不同命名路径引用；路径保留分支/续接出处和注释。路径顺序不产生计算依赖或证明前提。可分享的路径表示与真正执行分享是两件事，本原型不发送、不改权限。

## 与 KPB-14 的准确关系

KPB-14 是旧合同第 11 节的四道门，不是整份合同。新文档只增量细化 KPB-06 的描述、KPB-13 的责任以及 KPB-14 的下一轮试点；旧版本、冻结证据、四 epoch 接收规则与所有锁不变。

已有 G1/G2 是有限映射与结构比较；两条未绑定 claim 缺口不由新 schema 擅自补名。已有 G3 的 checked-roundtrip 本地复用与 synthetic native intake 分开保留。已有单个 adva 消费者的 machine 锁迁移不是对 synthetic intake 的采用，更不是全体消费者升级。本地测试不重新证明这些历史结果。

最先可以落地的就是此次描述格式和 library-only 负对照。随后选一个真实材料家目录，只映射、不搬迁；再另立消费锁和接收证据。要接计算或验证能力时，再按既有原生边界编写独立受限接收合同，不另造通用 loader 或注册中心。

## 测试结论应怎样读

MetadataConsistent 仅指格式和本地关系一致；所有报告始终保留 NotRun / NotGranted。实际请求 compute/verify 会拒绝；陌生 profile 或必需扩展无法解释则 Unknown。可选扩展可保留但忽略，其中即使出现 Verified 字段也无权威。缺失引用、伪成功标记、重复键、悬空关系与错误路径等有负对照。

输入/结构上限和费用计数只是文档原型的边界。字节预算耗尽与时间耗尽是 Unknown，结构格式不合规则是 Rejected。解析后的深度限制不是预先的内存隔离；完整试验另有十秒外层超时，记录导入、生成报告、所有正负对照和重复检查的总成本。没有运行全仓 Rust/CI，也没有原生数学验收。

Adva 核心词汇是否最小完备仍需先指定 profile、可表达任务、原语/派生词的判据与反例。不应让这个开放研究问题阻塞最小材料包试点，也不把这次的三个能力标签说成最终核心词汇。
