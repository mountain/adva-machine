# One iota package, two receiving uses

This original package is contributed under Unknown v0.3 by Codex (OpenAI),
through Mingli Yuan's authorized account proxy. Account use is not his technical
review, endorsement or a correctness guarantee. English is primary.

The same finite object is offered to adva's knowledge interface and
adva-machine's object-language interface. Each reception has its own contract,
receipt, replay and observed acknowledgment. The two receivers then execute
their own declared comparison. Neither receiver obtains the other's authority
merely because it has identical bytes.

## The retained generator and boundary

Source terms contain iota, binary application and three declared apertures.
The internal rules are iota x -> x S K, K x y -> x, and S x y z -> x z (y z).
Iota remains the sole primitive source combinator. I = iota iota,
K = iota (iota (iota iota)), and S = iota K are the existing pure-iota
encodings, with their applied behavior checked by the supplied native probes.
Construction {}, space [] and time () roles come from explicit entry and exit
policies. Source primitive choice and domain assignment are distinct inputs.

The compact prefix alphabet is `@` for application, `i/k/s` for the internal
combinators, and `a/b/c` for apertures. For example `@ia` represents iota a.
Only i/a/b/c occur as source leaves. Internal k/s are generated during reduction.
The tagged-tree and prefix representations must round-trip exactly.

## Mutual interpretation in this finite scope

Side A starts with the retained iota reduction records: source, complete local
redex/replacement, dependencies, cut terms and explicit observer policies.
Side B uses prefix terms, an independently written application-spine reducer,
event masks and an enumerated transition graph. Their common comparison is
the declared finite term/ledger relation, not a universal encoding of meaning.

The receiver reconstructs every admitted cut and transition, compares all
local replacements, counts schedules by dynamic programming, and checks clock
threshold cuts. S copying and K discarded arguments remain visible. The
imported occurrence names and final aperture fibres are documentary coordinates;
this checker does not recreate or certify the source's full annotated ancestry.
Exact full-process records remain separately pinned dependencies.

The shared object supplies an additional test: the existing Rust data machine
executes the supplied interpreter on pure-iota identity, discard and copy probes,
then replays their traces. These observations constrain the term reading; they
do not turn an external event mask into a native PSC0 CausalCut.

The comparison retains counterexamples to endpoint-only process identity,
concurrency as an equivalence relation of simultaneity, swapped iota expansion,
and a role reading inconsistent with the same bound bytes. Missing comparison
or object evidence and an exhausted join reserve leave the result Unknown and
do not advance the interpretation checkpoint. Both interface checks and all
three join predicates have explicit cost accounts. The three predicates are
not the framework's proposed 33/33/33/1 resource allocation.

These are actual adapter observations, authored by one agent. They are not
independent participants' agreement, human consent or a general communication
engine. A finite comparison can support one common reading while leaving
other readings unresolved.

## Simultaneity and the same process in real/imaginary time

A cut is a downward-closed completed-event set with a reconstructed term.
Independent events may be assigned equal or unequal observer clock readings.
A dependency must retain strict order. Concurrency need not be transitive:
for a<c and b independent of both, (a,b) and (b,c) may be concurrent while
(a,c) is ordered. Equal readings under a single clock are transitive.

S can expose independently progressing descendants with a shared origin.
K may discard a pending process while retaining the discarded term as history.
An equal final value therefore need not have equal cuts or histories.
Complete-redex observation and relocation make these conservative trace
families; the model does not claim minimal causality for unrestricted reduction.

One declared observation takes the undirected cut-graph Laplacian L=D-A and
H=L/(2*d_max). It uses the same H for U(t)=exp(-i*t*H) and
U(-i*tau)=exp(-tau*H). The four-cut diamond and chain have partition series
starting 4-2*beta and 4-(3/2)*beta. This package rechecks those first coefficients;
the earlier exact order-12 calculation remains a separately pinned observation.
Direction, full annotated ancestry and role policies remain residual data.
The heat walk admits backward edges and is not directed iota evaluation.
The operator parameter and observer clock are different inputs; physical
dynamics, spacetime and physical simultaneity are not derived by this package.

## How communicate and transport support one another

Communication supplies and tests the correspondence needed for the intended
use. Transport carries its exact presentation and preserves the agreed limits.
The receiver then tests the arrived presentation under its own intended use;
successful transport cannot repair a counterexample or unavailable observation.

The existing command remains `adva communicate`, while framework v2 calls its
documentary capability transport. Its native receipt grants only
documentary-reference use and explicitly records semantic verification NotRun
and native admission NotGranted. The separate `check.py` result records the
term/ledger comparison and native probes; neither record upgrades the other.

The source owns a small documentary catalog with home `logic`. The existing
wire profile prefixes material references with `adva-library/`; here that is
its serialization convention, not a claim that the files live in the global
adva-library catalog. No global catalog or machine dependency lock is changed.

## Reproduction and remaining dependencies

Use the exact package pin, checker, machine file pins and native binary in the
receiving records. With that machine's Python dependencies installed externally:

    python check.py --materials /path/to/received/materials \
      --expect-package PACKAGE_SHA256 --machine /path/to/adva-machine \
      --stage knowledge-after-reception --output /fresh/external/output

The machine receiver uses stage `machine-after-reception`. Every explicit run
consumes its own declared allowance; none triggers a retry or renewed fuel.
Fetching/building the pinned machine is a separate preparation step. A missing
required executable or pin refuses the check; there is no fallback engine.

The package contains the original v1 interpreter as an ordinary data-machine
program, original synthetic probes and compact v2 observations. It includes no
historical Java, MIT-derived fixture text, vendored dependencies or unrelated
repository content. Full annotated iota evidence remains at the pinned private
adva-iota revision and may require access. It is not required for documentary
reception or these compact comparisons; independently replaying the full
ancestry campaign does require those original inputs and its original contract.
