## Meaning and dependency

A frame binds one retained process to the representations and observations in
which a question is asked. The frame includes the domain boundaries, ordered
cut basis, complex structure, exponential rule, operator, metric, observer,
event clock, resources, evidence and residuals needed to interpret that process.

[Research 0135](../../docs/research/0135-reunderstanding-resource-frames-and-fuel.md)

## Finite laws and execution

For the real paired cut carrier, J has blocks [[0,-I],[I,0]], and H repeats
the declared cut-graph Laplacian observation on both components. The two
generators are -JH and -H. The coefficient substitution t=-i*tau relates their
exponentials. The checker fixes order twelve and a 3/13! tail bound on absolute
parameter <=1; it does not identify a truncated polynomial with the full flow.

An invertible change y=T x carries H and J by conjugacy, G by T^-T G T^-1,
and O by O T^-1. The approximation bound uses the transported metric. Positive
affine relabeling of the separate event clock preserves simultaneous groups.
Changing the observation question requires a new frame correspondence.

The existing GraftFrame and TransitionFrameV0 meanings are unchanged. This

## Receiving and reuse

The package crosses each repository boundary through the existing Rust
documentary transport profile. Each receiver then runs the separately scoped
frame comparison against its own previously received iota dependency.
`FrameCovarianceChecked` names that external finite comparison result;
`AcceptedDocumentary` names the native receipt. Receipt fields remain semantic
verification `NotRun` and native admission `NotGranted`.

Reusing the finite result requires the exact process, profile, dependency and
observation bindings. A missing binding leaves the interpretation unresolved;
a counterexample refuses the proposed correspondence. Broadening the process
family or changing the observer requires a separately bound continuation.
