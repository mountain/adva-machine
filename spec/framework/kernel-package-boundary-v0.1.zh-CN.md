# 内核与包边界合同 v0.1：中文支持说明

日期：2026-09-28。唯一维护归属：`mountain/adva-machine`。

本说明与英文合同的 KPB-01 至 KPB-14 对应，**英文为主**。这是约束后续设计与评审的工程合同；通用包加载器、切分证书检查器及验证链压缩系统尚未由此实现。既有执行规则、历史证据和依赖版本继续有效。

研究方向：苑明理。起草与来源审查：ChatGPT（OpenAI）；经苑明理授权账号提交，账号使用不代表其技术审阅、背书或正确性保证。本文为项目原创文档，按 Unknown v0.3 贡献。

## 有限观察者与内核职责

**KPB-01｜局部负责。** 知识可以不断增长，每次观察和验证只能占用有限资源。因此必须分割责任：一次调用先固定内核及执行规格、输入、解释、接受的前提与资源账户，结果保留未决前提和残差。小内核、有限内存、有限验证时间和表达能力是不同目标。切分证明可以降低内存占用，但不保证减少首次完整检查的总工作。

**KPB-02｜保留原有义务。** 新合同不得改写冻结证据、源与出现位置的身份、运行守卫、发布规则、Pascal 根增长义务或依赖锁。与旧规则冲突时须有明确的后继决策。新要求尚未满足，应记录缺口，不能把旧实验描述为已经接受新检查。

这里的内核，是某个执行规格据以接受判断的规则及其实现。可信基础还包括相关解析器、算术实现、配置和执行平台；规则少并不意味着这些依赖消失。目前适用的原生判断仍由 Rust 检查边界承担。

**KPB-03｜名称具有局部范围。** 名称是表示和解释的入口，不是已经完成的普遍概念。局部编号、文件名和摘要不产生原生身份。改名、拆分、特化、条件等价与统一须分别记录，说明保留、遗忘和未决部分，允许竞争解释并存。

学习基本词汇暂不宣告完备。现有研究接口以 `compute/verify/learn` 标记过程，以 `subject/method/object → history/result/evidence` 组织输入输出。是否增加原语，应由新增检查职责决定。

**KPB-04｜组合不可放宽。** 六词研究见证核是首个审计候选，尚未替换稳定 PSC0。`A=0` 表示实际与声明形成边界相合；每个子件先合法，不能让相反错误抵消。`M=1` 表示传输残差为一，不要求程序输出为一。端点对应、顺序、身份、历史和具体非零守卫都须保留；符号闭合不能消除中间 `ZeroFault`。更换算术域、相等关系、守卫或组合规则须另立版本。

## 学习、包与前提

**KPB-05｜提出与接受分开。** 学习方法可提出名称、猜想、策略、构造乃至内核修改，但须通过预先选定的接收规则才能获得使用资格。运行中不得自行更换检查器、接受条件，删除失败守卫或重置预算。合法的学习转移，其猜想仍可保持 `Proposed`。派生词可携带展开式交给现有规则检查；新原语或新的准入含义属于内核升级提案。

**KPB-06｜包须声明有限接口。** 包有唯一维护归属；文献、候选生成方法、可执行内容和证据具有不同准入路线。包描述须覆盖来源、检查器、输入输出及解释、前提与依赖、导出结论、证据与接收程序、资源约束、残差及生命周期。接口保留守卫并声明效果的执行边界；导出列明未解除前提，不能默许扩域。可以映射到既有格式，无须复制注册表。

`Gamma_P |-_{K_v} J_P` 仅表示：在前提 `Gamma_P` 下，由固定内核或执行规格 `K_v` 检查判断 `J_P`；它不是已经安装的新证明演算。

**KPB-07｜组合保留前提。** 下游只能复用范围、解释、守卫和效果符合请求的导出判断。未解除的前提随组合保留；用上游结论替换前提，需要适用的代入或运输规则及证据。同名不构成兼容，文献引用不自动成为推导边。若直接信任外部验证器的结论，验证器及其假设就进入明确声明的信任边界。

## 验证链切分与失效

**KPB-08｜切分不隐去责任。** 每处切分须记录上游导出、准确接口、下游用途、保留前提、证据位置及接收路线。可用路线包括本地重放、兼容上下文中的本地已验缓存、已实现的独立边界证明检查，或明确把外部结果作为条件前提。缺少接收实现的切分仍是提案；历史缺失不能悄悄变成公理。

缓存须绑定判断、前提、解释、检查器和版本、相关构建依赖与证据；新实例的输入和守卫仍须检查。复制他人的 `Verified` 标志、摘要或签名，不会继承其本地已验地位。

**KPB-09｜区分可用性与有效性。** 满足接收条件后，可以从工作内存移出旧证明正文，但不得删除冻结档案或义务。保留有限工作前沿与可追溯来源；无法重验须明示。引用不能保证字节永久存在。前提、解释或检查器变化后，应重新检查或提供兼容证据；后者须绑定新旧规格与检查器、判断、前提和迁移范围，经既定接收规则检查，不能自宣兼容。旧结论按原条件保留。纠错沿真实依赖边触发审查，不把所有引用者一概判错。本合同不承诺任意增长历史都能以固定成本验证。

**KPB-10｜结果与续行分别记账。** 区分局部已验、条件使用、材料或请求被拒、已验反例，以及未知／不完整／不可取得。坏证书不等于命题为假，缺证据也不覆盖已获得的反例。这些是报告区分，不新增 CLI 状态字串。

解析、解压、正规化、重放、检查和必要记录均须计费；未强制执行的限制不得声称已执行。续行绑定原问题、输入、版本、已验前缀、未决义务与已花资源。新增额度须另有有限合同。一般依赖环须拒绝，除非另有适用递归规则；全局防分叉记账和崩溃恢复需要独立机制。

执行规格须区分能留下合法续查记录的耗尽，与没有可恢复状态的强制终止。突然终止或缺少输出不表示接受；恢复须先重建最后可信边界，不能假定中断处已有可用检查点。

## 名称、升级与跨仓维护

**KPB-11｜跨仓引用须限定。** 研究序号只在所属仓库内有效。讨论注明仓库；文档链接注明完整路径；证据依赖再固定提交及所需摘要。`adva` 的 0207 是 constructive starvation，`adva-machine` 的 0207 是 Iota 拼写更名，不能按同号回退到本地文件。保留旧编号，每项新工作有唯一维护归属，其他仓保存引用或明确独立分叉。

明理指出此规则已在 R0 中记录；本次尚未定位其准确路径与版本，因此不声称已审阅。当前规则依据本次明确指示及已核对的碰撞实例；R0 来源补链保持待办，不猜测替代。

**KPB-12｜先分类再升级。** 别名、翻译和派生记法修改表示版本；搜索策略与领域包修改方法或包版本；新增原语、判断形式或准入规则，改变守卫、相等关系、可信验证器或证书解释，则须内核或执行规格后继版本。普通新定理不因此成为内核升级。记录规则、替代方案、异议、保留与失去的性质、依赖影响、正反检查、成本、残差和迁移退回路线。新二进制不自动升级旧判断。设计采纳与数学证据地位分开，沿用现有 ADR、claims 等机制。

**KPB-13｜一个归属，固定消费者。** `adva-machine` 维护规范、检查实现与符合性；`adva` 维护研究问题、方法、解释、实验及证据；`adva-library` 保持现有材料目录与接收条件。此分工不决定 library 的物理拆分，也不要求搬动历史文件。文档引用不升级执行锁。真正迁移内容须遵守既有接收契约，Git 同步不等于完成 Adva 交换。

## 实施与试点

**KPB-14｜分阶段推进。** 前三阶段形成试点，随后单独进入消费者采用：

1. **盘点。** 将现有见证规则、学习方法契约和一个 library 消费者映射到包字段，列出可信部件与缺口，不搬材料。
2. **文档包试点。** 描述上述三个单元，解析限定引用，生成定义、前提、导出与未决依赖的现状视图；通过只表示元数据一致。
3. **可执行边界试点。** 选择一种复用或切分路线，另立规格并实现，预先限定预算，分别测量首次检查与复用成本；保留旧加载器及四纪元祖先界限。

此后才以新依赖锁和新证据升级一个消费者；其余消费者保持原版本。试点须包含错误边界相消、断开的倒数比例、中间零、同名与同号冲突、缺失前提、伪造成功、缓存失效、预算耗尽、学习方法擅改规则、新实例身份以及移除生产包后的独立检查。以上是待执行验收条件，不能作为本文已经跑过的测试。

一次成功只建立一条有限接收路线，不意味着通用包组合、完备学习词汇或验证链问题已经解决。
